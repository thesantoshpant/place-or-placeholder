# Round-3 post hoc runs (EXP-B): specification

**Status.** Post hoc. Written on 2026-11-19, after the external review round 3 (`audits/final_round/TRIAGE_round3.md`, section C, "EXP-B") and **before any of these runs exists or is scored**. Nothing below has been computed from the new runs. Scoring is done later by a separate analysis agent. None of these runs reads, or is chosen from, the blinded run directories (BR S4, BR S2 no-history, BR S1 `sens_{yref,delay,ctrl}`).

Shared settings (unless stated): LightGBM quantile regression, the 9 deciles, 4 threads per chunk, the country's shared parameter set (its S1 L1 tuning; S5 uses the largest training country's L1 set, exactly as the seed-0 run of the cell), horizons **h ∈ {1, 4}**, the same features, folds, test years, LST screen and control kwargs as the seed-0 run each config is copied from. Every new config is generated by `scripts/run/round3_configs.py gen` and runs as an item of tier **T6** of the global scheduler (`scripts/run/scheduler.py`), through `scripts/run/r3_pipeline.sh`. New run directories never overwrite an existing run.

## S1. Extra seeds 1 and 2 (primary-family cells)

**What.** Seeds 1 and 2 of the four primary roles L3, L4, L3+C\*, L4+C\* (C\* = the cell's existing rule-v2 selection; it is not re-selected). The seed changes LightGBM bagging (`bagging_fraction` 0.8, `bagging_freq` 1) and, where C\* = C3, the fixed permutation of the C3 draw. Configs are byte-for-byte copies of the seed-0 config except `exp_name`, `seeds: [s]`, `horizons: [1, 4]`, `threads: 4` and (Taiwan) the test years.

**Why.** Seed SD (≈ 0.0001–0.0003 log-WIS) is of the same order as several G_excess estimates (audit 2 H3; RB referee). Brazil S1 already has seeds 0–2.

**Cells, in priority order** (scheduler order in T6):

|---|---|---|---|---|---|
| 1 | CO S1 | `colombia_s1_shared_*` | C1 | all 4 | |
| 2 | CO S2 | `colombia_s2_*` | C1 | all 4 | 5 folds |
| 3 | BR S5 | `brazil_s5_*` | C3 | all 4 | |
| 4 | TW S5 | `taiwan_s5_*` | C3 | **L3+C\*, L4+C\* only** | test years 2020–24 incl. 2021 |

Within each cell the C\* roles run first (seed 1 then seed 2), then L3/L4. Config names: `configs/<country>_<split>_r3_seed<s>_<role>.yaml` (run dirs `runs/<same stem>`), e.g. `colombia_s2_r3_seed1_L4_Cstar`.

**Compute cut (pre-declared, triage instruction).** The whole EXP-B set is estimated at ≈ 210 worker-h with every role, above the ~110 worker-h envelope. As instructed, the L3 and L4 (not C\*) seed runs of **TW S5 and PE S5** are not run (≈ 50 worker-h saved). For those two cells G_excess (L3+C\* vs L4+C\*) has seeds 0–2; G_emb and G_id stay seed 0 only. No other cut is made here; any further cut is the supervisor's decision.

**Decision (supervisor, recorded here as in TRIAGE C S1, made before any new seed is seen).** A cell's **primary estimate becomes the mean over seeds 0–2** wherever all three seeds exist for both roles of an estimand (the same "common seeds" rule as Brazil S1, `deviations_from_protocol.md` row 22). The seed-0 estimate is reported as a sensitivity analysis. A deviation row is to be added for this change. `configs/primary_cells.yaml` is switched to the 3-seed run lists by a later agent once all seeds exist; it is not edited here.

## S2. Taiwan S1 ladder and control panel including 2021

**What.** Test year 2021 only (h ∈ {1, 4}, seed 0), to be concatenated with the existing 2020/2022–24 runs, for: the baselines of `docs/results/tables/S1_baselines.csv` (L0 seasonal naive, NB GLM L1, LightGBM L1 with the Taiwan L1 parameters via `params_from`), L2 with the shared parameters, and the fixed control panel L3/L4 × C2/C3/C6 (copies of `configs/taiwan_s1_panel_*`, which `scripts/analysis/control_panel.py` scored; that script is not run here).

**Why.** The Taiwan S1 primary cell includes 2021 (row 25), but its ladder and panel rows did not (113,430 vs 141,645 scored rows). These runs remove that row-set split.

Configs: `configs/taiwan_s1_r3_tw2021_{baselines,L2,panel_L3_C2,panel_L4_C2,panel_L3_C3,panel_L4_C3,panel_L3_C6,panel_L4_C6}.yaml`.

## S3. Colombia S2 without case history (exploratory)

**What.** The no-history arm of `docs/methods/nohist_arm.md` (with its amendments), run for Colombia S2 exactly as Brazil S2 was run by `scripts/run/nohist_pipeline.sh`: levels N3, N4, N3+C\*, N4+C\*, N3+C1, N4+C1; Colombia's shared L1 parameters (31 leaves / min_data 100); LST screen on (as all Colombia runs); the Colombia S2 grouped folds; test years 2020–22; h ∈ {1, 4}. C\* is chosen at the 2019 origin among the target-free controls **C2, C3, C4 (705.11 km), C4s (min(D, fitted) = 130 km)** with selection rule v2 (`scripts/run/select_control.py --ref lgbm-N3`, priority C3 > C2 > C6 > C4s > C4; C6 is not defined in S2); C3/C4/C4s use 3 seeds at the 2019 origin, the final runs 1 seed. C1 (matched leave-out) is its own rung, not a C\* candidate.

**Why.** Referee request to check whether the Brazil no-history pattern holds in a second country. Exploratory; not in the primary family; no Holm adjustment with the main family.

Configs: `configs/colombia_s2_nohist_{controls_2019,N3,N4,N3_C1,N4_C1}.yaml`, then `{N3,N4}_Cstar.yaml` after the selection (pipeline stage `gen_cstar`).

## S4. Equal-budget tuning, Colombia S1

**What.** L3+C\* and L4+C\* (C\* = C1) are **tuned separately** on train 2018 → validate 2019 (the S1 tuning origin; the runner's `tune` block), over the same grid for both levels:
num_leaves {15, 31, 127} × min_data_in_leaf {100, 1000, 5000} × feature_fraction {0.3, 0.9} = 18 combinations, 400 rounds, learning rate 0.05, bagging 0.8/1, λ2 = 1; validation loss = mean pinball loss on log1p over q ∈ {0.1, 0.5, 0.9} and h ∈ {1, 4} (the original tuning protocol). Each level then runs the test years 2020–22 (h ∈ {1, 4}, seed 0) with its own best configuration. `feature_fraction` is already a LightGBM parameter that configs can set (`src/pop/models/lgbm.py` merges config params over its defaults); no code change was needed.

**Why.** Referee concern that one shared parameter set could favour or penalise the embedding level (capacity confound). G_excess "best-for-each" is reported beside the shared-parameter G_excess.

Configs: `configs/colombia_s1_r3_tuned_{L3,L4}_Cstar.yaml`. The tuning runs as its own pipeline stage (`round3_configs.py tune`, 4 threads) before the test chunks; it writes `runs/colombia_s1_r3_tuned_<lvl>_Cstar/tuning_lgbm-<lvl>+C1.{json,csv}`, which the test run then reuses.

## Execution

- Tier T6 order: CO S1 seeds → CO S2 seeds → EXP-A variant configs (`runs/queue/r3_expA_configs.txt`, one item per config, if present) → BR S5 seeds → TW S1 2021 ladder → TW S5 seeds → PE S5 seeds → CO S1 tuning → CO S2 no-history → CO S3 seeds → CO S4 seeds → PE S1 seeds → TW S1 seeds.
- Pipeline state: `runs/r3/<item>/` (stage markers, `pipeline.log`, `PIPELINE_DONE`).
- Budget: unchanged scheduler logic (60 threads minus other CPU, 4 threads per worker); new workers start only while ≥ 25 GiB memory is available.
